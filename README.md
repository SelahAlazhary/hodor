# نظام الحضور والانصراف — سلاح الأزهري

نظام متكامل لتسجيل حضور وانصراف الموظفين مع **حساب ساعات العمل تلقائياً طوال الشهر**،
لوحة تحكم للمدير، إشعارات على الهاتف، حضور تلقائي عبر شبكة الشركة، وعمل كامل **بدون إنترنت**
مع مزامنة تلقائية عند عودة الاتصال.

---

## المميزات

| المميزة | الوصف |
|---|---|
| ✅ تسجيل حضور | تلقائي عبر شبكة الشركة — زر التسجيل اليدوي مخفي عن الموظف افتراضياً |
| 🔴 تسجيل انصراف | يحسب ساعات اليوم تلقائياً (الفرق بين الحضور والانصراف) |
| 🚫 زر الغياب | يسجّل الغياب مع السبب ويبلّغ الإدارة فوراً |
| 📊 حساب شهري | إجمالي الساعات، أيام الحضور، الغياب، التأخير، متوسط اليوم |
| ⏱ وقت إضافي | لكل موظف دوامه الخاص (9←5 أو 10←6)، وما يزيد يُحسب إضافياً تلقائياً |
| ⚖ تعويض التأخير | من يتأخر ثم يعمل وقتاً إضافياً يُسجَّل أنه **لم يتأخر** ويُحتسب له الفائض |
| 👨‍💼 لوحة المدير | متابعة لحظية + أزرار حضور/انصراف/غياب يدوية + تحرير أجهزة + تقارير + تصدير |
| 🔔 إشعارات | إشعار للموظف عند الحضور والانصراف (بالساعات)، وإشعار للمدير بكل عملية |
| 🖥 حساب/جهاز التسجيل | المدير يختار: كل موظف من حسابه / جهاز معتمد واحد (كشك) / الاثنان |
| 📱 تثبيت إجباري | لا يسجّل الموظف حضوره من المتصفح — لا بد من تثبيت التطبيق أولاً |
| 🕐 توقيت واضح | ضبط المواعيد بـ«صباحاً/مساءً»، وعرض كل الأوقات المسجَّلة بنظام 24 ساعة |
| 🔔 تنبيه الانصراف | إشعار عند انتهاء الدوام ليسجّل الموظف انصرافه بنفسه — بلا انصراف تلقائي |
| 📡 تنبيه مغادرة المقر | إشعار للموظف وللمدير إذا خرج من شبكة الشركة دون تسجيل انصراف |
| 📢 إشعارات جماعية | المدير يرسل إشعاراً لموظف أو مجموعة أو الجميع فيصل على هواتفهم |
| 🔗 ربط بـQR | ربط حساب الموظف بهاتف أو كمبيوتر واحد بمسح رمز من لوحة المدير |
| 💻 تأكيد من الكمبيوتر | كلمة مرور حضور يعيّنها الموظف بنفسه، ولا تُقبل إلا داخل شبكة الشركة |
| 📶 حضور تلقائي بالواي فاي | يُسجَّل الحضور تلقائياً بمجرد اتصال الهاتف بشبكة الشركة — بدون أي ضغطة |
| 📴 يعمل أوفلاين | البيانات تُحفظ محلياً وتُرفع تلقائياً عند رجوع الإنترنت |
| 🕐 ساعة عالمية | الوقت من خادم Firebase بتوقيت القاهرة — تغيير ساعة الهاتف لا يفيد |
| 🔐 كلمة مرور مشفَّرة | مخزَّنة بصيغة SHA-256 في مسار لا تسمح القواعد بقراءته |
| 📱 حساب لهاتف واحد | الدخول بالاسم + رقم الهاتف، والحساب يُربط بجهاز واحد لا يعمل على غيره |
| ✋ تسجيل يدوي | المدير يسجّل «حضر / انصرف / غاب» لأي موظف بضغطة واحدة |
| 🎨 تصميم SVG | أيقونات ورسوم متجهية وحلقات تقدّم تتحرك مع البيانات |

## 1) تجهيز Firebase Realtime Database (خطوة إلزامية واحدة)

التخزين كله في **Realtime Database** لمشروعك `hodor-abfe0`، والقاعدة **مُنشأة وتعمل بالفعل** على العنوان:

```
https://hodor-abfe0-default-rtdb.firebaseio.com
```

يتبقّى شيء واحد مستحسن: من [Firebase Console](https://console.firebase.google.com/project/hodor-abfe0/database)
→ تبويب **Rules** → الصق محتوى ملف [`database.rules.json`](database.rules.json) → **Publish**
(قواعد وضع الاختبار تنتهي صلاحيتها بعد 30 يوماً، وهذه القواعد دائمة).

### لو غيّرت القاعدة أو منطقتها لاحقاً
سيكون العنوان مختلفاً (مثل `https://hodor-abfe0-default-rtdb.europe-west1.firebasedatabase.app`).
لا تحتاج تعديل الكود — افتح رابط التطبيق مرة واحدة بهذا الشكل ويُحفظ العنوان في الجهاز:

```
https://YOUR-SITE.vercel.app/?db=https://hodor-abfe0-default-rtdb.europe-west1.firebasedatabase.app
```

أو غيّر `DEFAULT_DB_URL` في أعلى ملف `js/firebase.js`.

> النظام لا يستخدم تسجيل دخول Firebase — الموظف يدخل باسمه فقط كما طلبت،
> لذلك القواعد مفتوحة على مسارات النظام فقط.

## 5) أول تشغيل

1. افتح الرابط → تبويب **مدير** → كلمة المرور: **`azhari2026`**
2. من **الإعدادات** غيّر كلمة المرور ومواعيد الدوام وسماح التأخير.
3. من **الموظفون** أضف أسماء الموظفين (الاسم فقط كافٍ).
4. من **الإعدادات → حساب تسجيل الحضور** اختر الطريقة:
   - **كل موظف من حسابه**: كل موظف يفتح الرابط ويكتب اسمه ويسجّل من هاتفه.
   - **جهاز محدد (كشك)**: افتح الرابط من جهاز الاستقبال مرة واحدة، ثم اعتمده من جدول **الأجهزة المسجّلة**، وسيسجّل حضور كل الموظفين من قائمة منسدلة.
   - **الاثنان معاً**.
5. اضغط **تفعيل إشعارات الحضور** ليصلك إشعار بكل عملية حضور أو انصراف أو غياب.

**دخول الموظف:** يفتح الرابط → تبويب **موظف** → يكتب **اسمه ورقم هاتفه** → دخول.

## ربط الحساب بهاتف واحد

- يدخل الموظف باسمه **ورقم هاتفه** معاً — لا بد أن يطابقا ما سجّلته الإدارة.
- أول هاتف يدخل منه يصبح **هاتفه المعتمد**، ولا يعمل الحساب على أي جهاز آخر بعدها.
- محاولة الدخول من هاتف ثانٍ تُرفض برسالة: «هذا الحساب مسجَّل على هاتف آخر».
- **لتغيير الهاتف:** لوحة المدير → **الموظفون** → زر **📱 هاتف جديد** أمام الموظف.
  يتحرّر الحساب فوراً، وأول هاتف يدخل منه بعدها يصبح المعتمد.
- عمود **الجهاز** في جدول الموظفين يوضّح: *مرتبط* (مع وقت الربط) أو *غير مرتبط*.
- **جهاز الكشك** المعتمد مستثنى من هذا القيد لأنه مشترك بين الجميع.
- الموظف **لا يملك زر تسجيل خروج** — التطبيق يبقى مفتوحاً على حسابه دائماً.
  للإدارة مخرج مخصّص: الضغط المطوّل على الشعار **5 ثوانٍ** ثم إدخال كلمة مرور المدير.

> ⚠ أي موظف قديم بدون رقم هاتف لن يستطيع الدخول — أضف رقمه من **الموظفون → تعديل**.

## 6) الحضور التلقائي عند الاتصال بشبكة الشركة

### كيف يعمل؟
المتصفحات **لا تسمح** لأي موقع بقراءة اسم شبكة الواي فاي (SSID) لأسباب أمنية.
لذلك يتعرّف النظام على شبكة الشركة عبر **عنوان الإنترنت العام (IP)** — فكل جهاز متصل
بواي فاي الشركة يخرج للإنترنت بنفس العنوان، وهذه هي الطريقة المعتمدة في أنظمة الحضور المهنية.

### طريقة الضبط (دقيقة واحدة)
1. من جهاز **متصل بواي فاي الشركة** افتح لوحة المدير → **الإعدادات**.
2. انزل إلى **الحضور التلقائي عبر شبكة الشركة** — سيظهر عنوان شبكتك الحالية.
3. اضغط **اعتماد هذه الشبكة** وسمّها (مثلاً: واي فاي المقر).
4. فعّل المفتاح **تسجيل الحضور تلقائياً**، وحدّد ساعات الفحص (مثلاً 6:00 ← 12:00).

> إذا كان عنوان الشركة متغيّراً، اكتب بداية النطاق منتهية بنقطة مثل `41.33.`
> ليقبل النظام كل العناوين التي تبدأ بها.

### متى يُسجَّل الحضور تلقائياً؟
| الحالة | النتيجة |
|---|---|
| التطبيق مفتوح أو في الخلفية | يُسجَّل خلال ثوانٍ من الاتصال بالشبكة |
| **لحظة اتصال الهاتف بالشبكة** | يُسجَّل فوراً عبر Background Sync حتى لو كان التطبيق **مغلقاً** |
| مثبَّت كتطبيق على أندرويد (Chrome) | فحص دوري إضافي كل ~15 دقيقة عبر Periodic Background Sync |
| فتح التطبيق بعد الوصول للعمل | يُسجَّل فوراً بمجرد الفتح، بدون ضغط أي زر |
| آيفون | لا تدعم Apple المزامنة الخلفية — يُسجَّل بمجرد فتح التطبيق |

الشروط: تفعيل الميزة من الإعدادات + وجود شبكة معتمدة + وقوع الوقت داخل نافذة الفحص +
عدم وجود تسجيل حضور أو غياب لليوم. ولا يعمل التسجيل التلقائي على **جهاز الكشك** (لأنه مشترك).

يظهر للموظف شريط أخضر أعلى الشاشة يوضّح حالة الفحص:
«لست على شبكة الشركة» / «جارٍ فحص الشبكة» / «تم تسجيل الحضور تلقائياً».

## 7) تثبيت التطبيق على الهاتف

- **أندرويد (Chrome):** افتح الرابط → يظهر زر **📲 تثبيت التطبيق**، أو من قائمة ⋮ → *تثبيت التطبيق / إضافة إلى الشاشة الرئيسية*.
- **آيفون (Safari):** زر المشاركة ⬆ → *إضافة إلى الشاشة الرئيسية*.

بعد التثبيت يعمل كتطبيق مستقل، ويعمل بدون إنترنت.

---

## 8) الساعة والتوقيت

الوقت في النظام **لا يُؤخذ من ساعة الجهاز إطلاقاً**:

- يُقرأ الفارق الزمني من خادم Firebase (`.info/serverTimeOffset`) عند كل تشغيل، فيبقى الوقت
  صحيحاً حتى لو كانت ساعة الهاتف متقدّمة أو متأخرة — **ولا يستطيع أحد تزوير وقت حضوره
  بتغيير ساعة هاتفه**.
- كل العرض والحسابات بتوقيت **القاهرة** (`Africa/Cairo`) مهما كانت المنطقة الزمنية المضبوطة
  على جهاز الموظف أو الإدارة.
- يُحفظ آخر فارق معروف على الجهاز، فيظل التوقيت سليماً أثناء انقطاع الإنترنت.
- تحت الساعة في شاشة الموظف مؤشّر يوضّح: **بتوقيت الخادم العالمي** أو *بتوقيت الجهاز*
  (إن تعذّرت المزامنة).

> لتغيير المنطقة الزمنية عدّل الثابت `TZ` في أعلى ملف `js/utils.js`.

## 9) كلمة مرور المدير

- الافتراضية عند أول تشغيل: **`azhari2026`** — غيّرها فوراً من
  **لوحة المدير ← الإعدادات ← أول بطاقة «كلمة مرور المدير»** (الحالية + الجديدة + التأكيد).
- لا تُخزَّن كنص مقروء أبداً: تُحفظ **بصمة SHA-256** في `settings/auth`،
  والقواعد تمنع قراءة هذا المسار نهائياً.
- التحقق يتم بمحاولة كتابة البصمة في `adminAuth` — تقبلها القاعدة فقط إذا طابقت
  البصمة المخزَّنة، فلا يقرأ التطبيق كلمة المرور ولا بصمتها إطلاقاً.
- تغييرها يتطلب معرفة الحالية، ويعمل الدخول بدون إنترنت عبر بصمة محفوظة على الجهاز.

> ⚠ **مطلوب:** انشر ملف [`database.rules.json`](database.rules.json) في
> **Firebase → Realtime Database → Rules → Publish**. بدونه لا تعمل:
> إخفاء كلمة المرور، ورموز الربط QR، وإشعارات الإدارة.

## ربط الجهاز عبر رمز QR

من **الموظفون ← زر «ربط بـQR»** تظهر نافذة برمز يمسحه الموظف من الجهاز المراد ربطه
(هاتف أو **كمبيوتر شخصي**). عند فتح الرابط يُربط الحساب بذلك الجهاز وحده ويُفتح مباشرة
دون كتابة اسم أو رقم. الرمز صالح **15 دقيقة ولمرة واحدة**، ويُولَّد من خدمة بايثون
عبر `/api/qr`.

---

## تأكيد الحضور من الكمبيوتر بكلمة مرور

- يعيّن **الموظف بنفسه** كلمة مرور حضور من شاشته (تُحفظ مشفَّرة SHA-256 ولا يعرفها أحد).
- على الكمبيوتر تظهر بطاقة **«تأكيد الحضور»** إن لم يكن سجّل حضوره من الهاتف.
- **لا يُقبل التأكيد إلا داخل شبكة الشركة** — خارجها يُعطَّل الحقل وتظهر رسالة واضحة.
- الحضور لا يُقبل إذن إلا بإحدى ثلاث: **شبكة الشركة تلقائياً**، أو **كلمة مرور الموظف داخل الشبكة**،
  أو **تسجيل المدير** يدوياً.

### تشغيل التطبيق تلقائياً بعد إعادة تشغيل الكمبيوتر

تظهر للموظف على الكمبيوتر بطاقة بالخطوات: ثبّت التطبيق ← افتح `chrome://apps`
← بالزر الأيمن على أيقونة التطبيق ← فعّل **Start app when you sign in**.

## تنبيه بقاء الموظف خارج الشبكة

إذا ظل الموظف خارج شبكة الشركة **ساعة أو أكثر** وحضوره ما زال مفتوحاً، يصل المدير إشعار:
«⏳ موظف خارج الشبكة منذ ساعة — تحقّق من وجوده»، ويتكرّر كل ساعة (حتى 4 مرات).

---

## إشعارات الإدارة

من لسان **«إرسال إشعار»** يختار المدير: **كل الموظفين** أو **موظفين محددين**، ويكتب
عنواناً ونصاً فيصل إشعاراً على هواتفهم ويظهر في شاشتهم ضمن **إشعارات الإدارة**.
تُعرض الإشعارات المرسلة في قائمة يمكن حذف أي منها.

---

## منع تسجيل الحضور من خارج الشركة

زر **«تسجيل حضور»** مخفي عن الموظف افتراضياً حتى لا يسجّل حضوره وهو في بيته.
تبقى ثلاث طرق موثوقة لتسجيل الحضور:

1. **تلقائياً** بمجرد اتصال هاتفه بشبكة الواي فاي الخاصة بالشركة (يثبت وجوده فعلياً).
2. من **جهاز الاستقبال (الكشك)** المعتمد.
3. **يدوياً من المدير** بزر «حضر» في صفحة *حضور اليوم*.

يرى الموظف بدلاً من الزر ملاحظة: «حضورك يُسجَّل تلقائياً بمجرد اتصال هاتفك بشبكة الشركة».
أما **زر الانصراف فيبقى ظاهراً** لأنه هو من يحدّد وقته الإضافي بدقة.

> لإظهار الزر مجدداً: **الإعدادات ← طريقة تسجيل الحضور ← السماح للموظف بتسجيل حضوره يدوياً**.
> ويحذّرك النظام إن أغلقت التسجيل اليدوي بلا حضور تلقائي ولا جهاز كشك.

## تعويض التأخير بالوقت الإضافي

إذا تأخر الموظف ثم عمل بعد نهاية دوامه حتى غطّى تأخيره وزاد، يُسجّل النظام تلقائياً
أنه **لم يتأخر** ويحتسب الفائض وقتاً إضافياً.

| الحالة (دوام 9 ← 5 = 8 ساعات) | النتيجة |
|---|---|
| حضر 10:00 وانصرف 7:00 م ← عمل 9 ساعات | **لا تأخير** + ساعة إضافية |
| حضر 10:00 وانصرف 6:00 م ← عمل 8 ساعات | متأخر (لم يعمل زيادة) |
| حضر 10:00 وانصرف 5:00 م ← عمل 7 ساعات | متأخر |
| حضر 9:10 (داخل السماح) | لا تأخير أصلاً |

- **فترة السماح**: التأخير أقل من **15 دقيقة** لا يُحتسب إطلاقاً (قابلة للتعديل من الإعدادات).
- يظهر في السجل والتقارير وسم **«تأخير معوَّض»** مع عدد دقائق التأخير الأصلي — للشفافية.
- يصل الموظف عند انصرافه إشعار: «✅ عُوِّض تأخيرك (45 د) بالوقت الإضافي».

## تنبيه الخروج من الشبكة بلا انصراف

إذا غادر الموظف مقر الشركة (فتغيّر عنوان شبكته) وهو ما زال مسجَّلاً حاضراً:

- **يصل الموظف** إشعار: «⚠️ لم تسجّل انصرافك — خرجت من شبكة الشركة».
- **يصل المدير** إشعار فوري: «⚠️ خروج بلا انصراف — فلان خرج الساعة … ولم يسجّل انصرافه»،
  ويظهر الحدث في *آخر الأحداث* بلون تحذيري.

### يفرّق النظام بين حالتين

| الحالة | رسالة الموظف | إشعار المدير |
|---|---|---|
| غادر **بعد** انتهاء دوامه | «انتهى دوامك وغادرت — سجّل انصرافك» (تذكير هادئ) | «غادر بعد انتهاء دوامه» بلون تنبيه |
| غادر **قبل** انتهاء دوامه | «خرجت من شبكة الشركة قبل انتهاء دوامك» | «غادر قبل انتهاء دوامه» بلون خطر |

### إنهاء اليوم على لحظة المغادرة

يسجّل النظام **لحظة مغادرة الموظف** للمقر، ويظهر للمدير في *حضور اليوم* زر
**«أنهِ عند 02:32 م»** يُغلق يوم الموظف على وقت خروجه الفعلي — بدل تركه مفتوحاً أو
تقدير الوقت. تُحسب ساعاته ووقته الإضافي وتعويض تأخيره من هذه اللحظة بدقة.

للدقة يشترط النظام **قراءتين متتاليتين** خارج الشبكة قبل التنبيه حتى لا ينبّه لانقطاع
لحظي في الواي فاي، وينبّه **مرة واحدة يومياً**، ويُعيد التسليح تلقائياً إذا عاد الموظف للشبكة.
يعمل التنبيه والتطبيق مفتوح أو في الخلفية، وكذلك **والتطبيق مغلق** على أندرويد.

## تنبيه انتهاء الدوام

عند بلوغ موعد انصراف الموظف يصله إشعار **«🔔 حان وقت الانصراف»**، ويتكرّر كل 30 دقيقة
(حتى ساعتين) إن لم يسجّل انصرافه، ويعرض له الوقت الإضافي المتراكم لحظة بلحظة.

> **لا يوجد انصراف تلقائي إطلاقاً** — الموظف هو من يضغط زر الانصراف، وبذلك يُحتسب
> وقته الإضافي بدقة من لحظة خروجه الفعلية.

يعمل التنبيه والتطبيق مفتوح أو في الخلفية، وكذلك والتطبيق **مغلق** على أندرويد.

## 10) خدمة بايثون — التقارير والمهام التلقائية

بجانب التطبيق تعمل خدمة **FastAPI** على نفس الرابط، تتولّى الأعمال الثقيلة
دون أن تعطّل عمل التطبيق بدون إنترنت:

| الرابط | الوظيفة |
|---|---|
| `/api/health` | حالة الخدمة والوقت الرسمي بتوقيت القاهرة |
| `/api/summary?month=YYYY-MM` | ملخّص شهري بصيغة JSON |
| `/api/report?month=YYYY-MM` | **تقرير Excel شهري**: ملخّص لكل موظف + ورقة تفاصيل الأيام |
| `/api/report/daily?date=YYYY-MM-DD` | تقرير Excel ليوم واحد |
| `/api/auto-absent` | تسجيل غياب كل من لم يحضر (يعمل تلقائياً يومياً) |
| `/api/cleanup` | يعرض السجلات اليتيمة (لموظفين محذوفين) — `?dry=false` للحذف |
| `/api/docs` | صفحة توثيق تفاعلية لكل النقاط |

- ملفات Excel منسّقة **من اليمين لليسار** بألوان الشركة وحدود وصفوف إجمالي.
- الأزرار موجودة في لوحة المدير: **تقرير Excel** في التقرير الشهري و**Excel** في جدول اليوم.
- منطق الساعات والوقت الإضافي في بايثون **مطابق تماماً** لمنطق التطبيق.
- **المهمة اليومية**: يسجّل Vercel Cron الغياب تلقائياً الساعة 6 مساءً بتوقيت القاهرة
  (`0 15 * * *` بتوقيت UTC)، ويتخطّى الإجازة الأسبوعية (الجمعة افتراضياً — عدّلها
  بإضافة `weekend: [5,6]` في `settings/global`).

> الخدمة تقرأ من قاعدة البيانات مباشرة عبر REST — لا تحتاج أي مفاتيح أو إعدادات إضافية.

## 11) الإشعارات — ملاحظة مهمة

الإشعارات تعمل عبر Web Notifications ويُشترط:

- فتح الرابط عبر **HTTPS** (رابط Vercel يوفّره تلقائياً).
- الموافقة على طلب الإذن عند أول دخول.
- على **آيفون** لازم يكون التطبيق **مثبَّتاً على الشاشة الرئيسية** أولاً (شرط من Apple).
- تصل الإشعارات والتطبيق مفتوح أو يعمل في الخلفية. لو أردت إشعارات تصل والتطبيق **مغلق تماماً**،
  فعّل Firebase Cloud Messaging وأضف مفتاح VAPID — ملف `sw.js` جاهز لاستقبال `push` بالفعل.

## بنية البيانات في Realtime Database

```
settings/global              إعدادات الشركة وطريقة التسجيل وشبكات الحضور التلقائي
settings/auth                بصمة كلمة مرور المدير (القراءة ممنوعة بالقواعد)
adminAuth/{deviceId}         مسار التحقق من كلمة المرور دون كشفها
employees/{empId}            الاسم، الوظيفة، الهاتف، مواعيد الدوام، الحالة
attendance/{YYYY-MM-DD}/{empId}   الحضور، الانصراف، الدقائق المحسوبة، الحالة
events/{eventId}             سجل الأحداث الذي تُبنى منه إشعارات المدير
devices/{deviceId}           الأجهزة المسجّلة لاختيار جهاز الكشك
```

## كيف يعمل بدون إنترنت؟

كل عملية كتابة (حضور، انصراف، غياب، إضافة موظف…) تُحفظ أولاً في **طابور محلي**
داخل الهاتف (`localStorage`)، وتظهر في الواجهة فوراً. عند عودة الإنترنت تُرفع بالترتيب
إلى Realtime Database تلقائياً. **لا تُحذف أي عملية إلا بعد تأكيد الخادم**، ويعيد النظام
المحاولة تلقائياً حتى لو أُغلق التطبيق أو أُعيد تشغيل الهاتف. شريط أعلى الشاشة يوضح
حالة الاتصال وعدد العمليات المنتظرة.
