# نظام الحضور والانصراف — سلاح الأزهري

نظام متكامل لتسجيل حضور وانصراف الموظفين مع **حساب ساعات العمل تلقائياً طوال الشهر**،
لوحة تحكم للمدير، إشعارات على الهاتف، حضور تلقائي عبر شبكة الشركة، وعمل كامل **بدون إنترنت**
مع مزامنة تلقائية عند عودة الاتصال.

---

## المميزات

| المميزة | الوصف |
|---|---|
| ✅ تسجيل حضور | زر واحد، مع تحديد التأخير تلقائياً حسب موعد الدوام |
| 🔴 تسجيل انصراف | يحسب ساعات اليوم تلقائياً (الفرق بين الحضور والانصراف) |
| 🚫 زر الغياب | يسجّل الغياب مع السبب ويبلّغ الإدارة فوراً |
| 📊 حساب شهري | إجمالي الساعات، أيام الحضور، الغياب، التأخير، متوسط اليوم |
| 👨‍💼 لوحة المدير | متابعة لحظية + أزرار حضور/انصراف/غياب يدوية + تقارير + تصدير + طباعة |
| 🔔 إشعارات | إشعار للموظف عند الحضور والانصراف (بالساعات)، وإشعار للمدير بكل عملية |
| 🖥 حساب/جهاز التسجيل | المدير يختار: كل موظف من حسابه / جهاز معتمد واحد (كشك) / الاثنان |
| 📱 تطبيق على الهاتف | PWA يُثبَّت على الشاشة الرئيسية ويعمل كتطبيق حقيقي |
| 📶 حضور تلقائي بالواي فاي | يُسجَّل الحضور تلقائياً بمجرد اتصال الهاتف بشبكة الشركة — بدون أي ضغطة |
| 📴 يعمل أوفلاين | البيانات تُحفظ محلياً وتُرفع تلقائياً عند رجوع الإنترنت |

## 1) تجهيز Firebase Realtime Database (خطوة إلزامية واحدة)

التخزين كله في **Realtime Database** لمشروعك `hodor-abfe0`، والقاعدة **مُنشأة وتعمل بالفعل** على العنوان:

```
https://hodor-abfe0-default-rtdb.firebaseio.com
```

يتبقّى شيء واحد مستحسن: من [Firebase Console](https://console.firebase.google.com/project/hodor-abfe0/database)
→ تبويب **Rules** → الصق محتوى ملف [`database.rules.json`](database.rules.json) → **Publish**
(قواعد وضع الاختبار تنتهي صلاحيتها بعد 30 يوماً، وهذه القواعد دائمة).

### لو غيّرت القاعدة أو منطقتها لاحقاً
سيكون العنوان مختلفاً (مثل `https://hodor-abfe0-default-rtdb.europe-west1.firebasedatabase.app`).
لا تحتاج تعديل الكود — افتح رابط التطبيق مرة واحدة بهذا الشكل ويُحفظ العنوان في الجهاز:

```
https://YOUR-SITE.vercel.app/?db=https://hodor-abfe0-default-rtdb.europe-west1.firebasedatabase.app
```

أو غيّر `DEFAULT_DB_URL` في أعلى ملف `js/firebase.js`.

> النظام لا يستخدم تسجيل دخول Firebase — الموظف يدخل باسمه فقط كما طلبت،
> لذلك القواعد مفتوحة على مسارات النظام فقط.

## 4) الربط مع Vercel

1. ادخل [vercel.com/new](https://vercel.com/new) وسجّل بحساب GitHub.
2. اختر المستودع → **Import**.
3. الإعدادات: `Framework Preset = Other` ، و **اترك حقول Build و Output فارغة** (الموقع ثابت).
4. اضغط **Deploy** — خلال ثوانٍ يظهر رابط مثل `https://azhari-attendance.vercel.app`.

أي تعديل ترفعه على GitHub يُنشر تلقائياً على Vercel.

---

## 5) أول تشغيل

1. افتح الرابط → تبويب **مدير** → كلمة المرور: **`azhari2026`**
2. من **الإعدادات** غيّر كلمة المرور ومواعيد الدوام وسماح التأخير.
3. من **الموظفون** أضف أسماء الموظفين (الاسم فقط كافٍ).
4. من **الإعدادات → حساب تسجيل الحضور** اختر الطريقة:
   - **كل موظف من حسابه**: كل موظف يفتح الرابط ويكتب اسمه ويسجّل من هاتفه.
   - **جهاز محدد (كشك)**: افتح الرابط من جهاز الاستقبال مرة واحدة، ثم اعتمده من جدول **الأجهزة المسجّلة**، وسيسجّل حضور كل الموظفين من قائمة منسدلة.
   - **الاثنان معاً**.
5. اضغط **تفعيل إشعارات الحضور** ليصلك إشعار بكل عملية حضور أو انصراف أو غياب.

**دخول الموظف:** يفتح الرابط → تبويب **موظف** → يكتب اسمه → دخول.

## 6) الحضور التلقائي عند الاتصال بشبكة الشركة

### كيف يعمل؟
المتصفحات **لا تسمح** لأي موقع بقراءة اسم شبكة الواي فاي (SSID) لأسباب أمنية.
لذلك يتعرّف النظام على شبكة الشركة عبر **عنوان الإنترنت العام (IP)** — فكل جهاز متصل
بواي فاي الشركة يخرج للإنترنت بنفس العنوان، وهذه هي الطريقة المعتمدة في أنظمة الحضور المهنية.

### طريقة الضبط (دقيقة واحدة)
1. من جهاز **متصل بواي فاي الشركة** افتح لوحة المدير → **الإعدادات**.
2. انزل إلى **الحضور التلقائي عبر شبكة الشركة** — سيظهر عنوان شبكتك الحالية.
3. اضغط **اعتماد هذه الشبكة** وسمّها (مثلاً: واي فاي المقر).
4. فعّل المفتاح **تسجيل الحضور تلقائياً**، وحدّد ساعات الفحص (مثلاً 6:00 ← 12:00).

> إذا كان عنوان الشركة متغيّراً، اكتب بداية النطاق منتهية بنقطة مثل `41.33.`
> ليقبل النظام كل العناوين التي تبدأ بها.

### متى يُسجَّل الحضور تلقائياً؟
| الحالة | النتيجة |
|---|---|
| التطبيق مفتوح أو في الخلفية | يُسجَّل خلال ثوانٍ من الاتصال بالشبكة |
| **مثبَّت كتطبيق على أندرويد (Chrome)** | يعمل والتطبيق **مغلق** عبر Periodic Background Sync — يفحص كل ~15 دقيقة |
| فتح التطبيق بعد الوصول للعمل | يُسجَّل فوراً بمجرد الفتح، بدون ضغط أي زر |
| آيفون | لا تدعم Apple المزامنة الخلفية — يُسجَّل بمجرد فتح التطبيق |

الشروط: تفعيل الميزة من الإعدادات + وجود شبكة معتمدة + وقوع الوقت داخل نافذة الفحص +
عدم وجود تسجيل حضور أو غياب لليوم. ولا يعمل التسجيل التلقائي على **جهاز الكشك** (لأنه مشترك).

يظهر للموظف شريط أخضر أعلى الشاشة يوضّح حالة الفحص:
«لست على شبكة الشركة» / «جارٍ فحص الشبكة» / «تم تسجيل الحضور تلقائياً».

## 7) تثبيت التطبيق على الهاتف

- **أندرويد (Chrome):** افتح الرابط → يظهر زر **📲 تثبيت التطبيق**، أو من قائمة ⋮ → *تثبيت التطبيق / إضافة إلى الشاشة الرئيسية*.
- **آيفون (Safari):** زر المشاركة ⬆ → *إضافة إلى الشاشة الرئيسية*.

بعد التثبيت يعمل كتطبيق مستقل، ويعمل بدون إنترنت.

---

## 8) الساعة والتوقيت

الوقت في النظام **لا يُؤخذ من ساعة الجهاز إطلاقاً**:

- يُقرأ الفارق الزمني من خادم Firebase (`.info/serverTimeOffset`) عند كل تشغيل، فيبقى الوقت
  صحيحاً حتى لو كانت ساعة الهاتف متقدّمة أو متأخرة — **ولا يستطيع أحد تزوير وقت حضوره
  بتغيير ساعة هاتفه**.
- كل العرض والحسابات بتوقيت **القاهرة** (`Africa/Cairo`) مهما كانت المنطقة الزمنية المضبوطة
  على جهاز الموظف أو الإدارة.
- يُحفظ آخر فارق معروف على الجهاز، فيظل التوقيت سليماً أثناء انقطاع الإنترنت.
- تحت الساعة في شاشة الموظف مؤشّر يوضّح: **بتوقيت الخادم العالمي** أو *بتوقيت الجهاز*
  (إن تعذّرت المزامنة).

> لتغيير المنطقة الزمنية عدّل الثابت `TZ` في أعلى ملف `js/utils.js`.

## 9) كلمة مرور المدير

- الافتراضية عند أول تشغيل: **`azhari2026`** — غيّرها فوراً من **الإعدادات**.
- لا تُخزَّن كنص مقروء أبداً: تُحفظ **بصمة SHA-256** في `settings/auth`،
  والقواعد تمنع قراءة هذا المسار نهائياً.
- التحقق يتم بمحاولة كتابة البصمة في `adminAuth` — تقبلها القاعدة فقط إذا طابقت
  البصمة المخزَّنة، فلا يقرأ التطبيق كلمة المرور ولا بصمتها إطلاقاً.
- تغييرها يتطلب معرفة الحالية، ويعمل الدخول بدون إنترنت عبر بصمة محفوظة على الجهاز.

> ⚠ لتفعيل الحماية الكاملة يجب نشر ملف [`database.rules.json`](database.rules.json)
> في **Firebase → Realtime Database → Rules → Publish**.

## 10) الإشعارات — ملاحظة مهمة

الإشعارات تعمل عبر Web Notifications ويُشترط:

- فتح الرابط عبر **HTTPS** (رابط Vercel يوفّره تلقائياً).
- الموافقة على طلب الإذن عند أول دخول.
- على **آيفون** لازم يكون التطبيق **مثبَّتاً على الشاشة الرئيسية** أولاً (شرط من Apple).
- تصل الإشعارات والتطبيق مفتوح أو يعمل في الخلفية. لو أردت إشعارات تصل والتطبيق **مغلق تماماً**،
  فعّل Firebase Cloud Messaging وأضف مفتاح VAPID — ملف `sw.js` جاهز لاستقبال `push` بالفعل.

## بنية البيانات في Realtime Database

```
settings/global              إعدادات الشركة وطريقة التسجيل وشبكات الحضور التلقائي
settings/auth                بصمة كلمة مرور المدير (القراءة ممنوعة بالقواعد)
adminAuth/{deviceId}         مسار التحقق من كلمة المرور دون كشفها
employees/{empId}            الاسم، الوظيفة، الهاتف، مواعيد الدوام، الحالة
attendance/{YYYY-MM-DD}/{empId}   الحضور، الانصراف، الدقائق المحسوبة، الحالة
events/{eventId}             سجل الأحداث الذي تُبنى منه إشعارات المدير
devices/{deviceId}           الأجهزة المسجّلة لاختيار جهاز الكشك
```

## كيف يعمل بدون إنترنت؟

كل عملية كتابة (حضور، انصراف، غياب، إضافة موظف…) تُحفظ أولاً في **طابور محلي**
داخل الهاتف (`localStorage`)، وتظهر في الواجهة فوراً. عند عودة الإنترنت تُرفع بالترتيب
إلى Realtime Database تلقائياً. **لا تُحذف أي عملية إلا بعد تأكيد الخادم**، ويعيد النظام
المحاولة تلقائياً حتى لو أُغلق التطبيق أو أُعيد تشغيل الهاتف. شريط أعلى الشاشة يوضح
حالة الاتصال وعدد العمليات المنتظرة.
